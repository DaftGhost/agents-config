# 交付物、量级与资料选择

完成入口的调查与缺口处理后，依据已查明的范围、依赖和影响，选择能支撑评审和验收的最小文档量级，并简述依据。量级用于组织文档内容。

| 文档量级 | 选择依据 | 交付物与结构 |
| --- | --- | --- |
| 轻量 | 单一场景或局部变更，沿用现有规则，无需独立展开高影响决策 | 一份方案，合并需求、实现、验证与交付安排；读取 [轻量流程与模板](lightweight.md) |
| 常规 | 完整功能，涉及多个场景或模块，有明确的规则、依赖和失败分支 | 按需求或技术阶段使用 PRD、TDD 常规模板 |
| 深入 | 跨系统或多角色，存在复杂状态、重要依赖、迁移，或数据、安全、兼容等高影响决策 | 使用阶段的深入模板，分章展开关键边界、流程、风险和交付安排 |

常规和深入任务按当前阶段读取 [PRD 流程](prd/task.md) 或 [TDD 流程](tdd/task.md)。同时需要两者时，先梳理需求，再以已确认需求为设计基线；进入下一阶段时再加载该阶段资料，两份文档可分别选择量级。

用户指定的交付物、路径、篇幅、结构及仓库强制模板优先。目标路径依次采用用户指定路径、仓库约定或已有文件；未指定时，轻量方案为 `docs/<主题>.md`，PRD 为 `docs/<主题>/prd.md`，TDD 为 `docs/<主题>/tdd.md`。轻量 PRD 或 TDD 取共享轻量模板中请求涉及的内容；明确要求分文档时，将需求放入 PRD，实现与验证放入 TDD，通过需求编号和文件引用关联，不另建合并文档。局部修改沿用原文件、结构和编号。审查时按内容覆盖判断，阶段流程仅用于核对约束和证据来源。

流程说明分支内的执行顺序，`document.md` 说明内容要求，`template-*.md` 只提供结构。读取条件满足时再加载对应文件，已加载内容直接复用；局部修改和定向审查只读取相关内容要求，全面审查读取完整规范。

篇幅为参考，以关键规则、失败结果、证据和验证方式是否齐全为准。章节和表格可合并；不适用或超出范围的内容简述原因，详细资料用链接引用。复杂度集中在一处时只展开该节；结构无法表达关键边界时升级量级。篇幅受限时说明未覆盖的影响。跨模板引用使用章节名或实际位置。
