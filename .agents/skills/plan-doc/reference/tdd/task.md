# TDD 阶段任务流程

## 执行步骤

1. **确认需求基线**
   - 查找 PRD、评审记录或用户需求说明，确认版本、状态和未决项。
   - PRD 为草稿时，TDD 也保持草稿。没有 PRD 时，需求说明已讲清问题、预期结果和范围即可继续，否则先梳理需求。
   - 完成时，设计输入及其确认状态可追溯，未决产品问题已与可采用的需求分开。

2. **检查系统与变更边界**
   - 阅读仓库指引及需求相关的实现、调用方、契约、数据、配置、迁移、测试与部署约定，跟踪调用链和状态变化。静态代码无法证明的运行时或外部行为列为待核实。
   - 检查扩展点和拟变更对象前，读取 [技术方案的变更边界](change-boundaries.md)。将需求关联到设计对象，列明涉及和排除的模块、接口、数据及发布单元。
   - 完成时，每项拟变更均有需求或缺口依据，通用能力变更有调用方及兼容影响分析。

3. **形成设计与验证方案**
   - 形成主方案前，读取 [内容规范](document.md) 的相关部分，全面设计读取全文。按其内容职责形成关键分支、变更对象、验证及交付安排；实施对象写到可定位的位置，不展开为逐步编码指令。
   - 按入口的提问规则处理影响组件边界、契约、数据、兼容、安全、性能预算或验收的选择。
   - 完成时，每项已确认需求都关联到设计和验证方式，关键设计缺口已列为开放问题。

4. **起草或修改并交付**
   - 创建或重构文档结构时，按已选量级读取 [常规模板](template-standard.md) 或 [深入模板](template-detailed.md)；沿用已有结构时无需加载模板。
   - 按已加载的内容规范填写。
   - 按入口的复核与交付要求完成，同时遵守第 1 步的需求基线约束。
