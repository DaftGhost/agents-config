# 提问细则

仅对答案会改变当前阶段目标、范围、验收或设计的未决选择提问；局部修改只评估受影响内容。

| 提问量级 | 未决决策 | 沟通投入参考 |
| --- | --- | --- |
| 轻量 | 沿用已有决定，少量局部歧义 | 0–2 个问题，信息充分时直接起草或修改 |
| 常规 | 多个场景或模块的范围、规则或验收取舍 | 3–5 个问题，先解决前置选择 |
| 深入 | 跨系统或多角色的依赖、冲突，或数据、安全、兼容等高影响取舍 | 6–10 个问题，按决策依赖分批展开 |

数量既非配额，也非上限：复杂任务可以零提问，局部任务的高影响决策也需深入确认。用户指定数量或节奏时优先遵循，限制内无法解决的缺口注明影响。

- **分批**：前置答案决定后续问题是否成立时，先单独问前置问题；独立且背景相同的问题可同批提出，通常每批 1–3 个，深入任务可至 3–4 个。单题只含一个决策。AskUserQuestion 可用时使用该工具，并遵守工具数量限制。
- **说明影响**：局部歧义简述缺口与影响；重大取舍补充证据、可行选项、建议及后果，建议标为未确认。
- **收敛**：每轮删除已回答或失效的问题，补充新发现的关键缺口。已无阻塞起草的问题时，返回总体工作流继续；其余按入口的未决项规则记录。

## 判断示例

- 跨系统迁移的约束、兼容和切换策略均已确认 → 使用深入文档，零提问。
- 局部导出增加敏感字段，授权范围未定 → 需求与实现边界仍集中时可用轻量文档，但需确认授权范围；若需展开独立的安全设计，再升级文档量级。
- 目标指标已确定，当前基线缺失 → 保留目标并核验基线，不重新询问目标；查不到则标为待核实。
