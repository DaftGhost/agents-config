# 文档审查流程

1. **确定核对要求**：沿用已定位的待审文档、版本、审查范围和需求来源，以及入口已选的阶段与量级；完成时，待查内容及所依据的要求明确。
2. **核对内容与证据**：轻量方案按入口已加载的轻量模板核对；PRD/TDD 读取对应的 [PRD 内容规范](prd/document.md) 或 [TDD 内容规范](tdd/document.md)，定向审查只读相关部分，全面审查读全文。核对所选阶段流程中的证据要求和专有约束；涉及技术变更时读取 [变更边界规则](tdd/change-boundaries.md)。检查需求、验收、设计、图表、未决项和批准记录的适用内容是否一致，查证会影响结论的事实。
3. **整理发现**：每项发现注明文档位置、违反的要求或证据、具体影响和修改建议，无法核实的另列并注明核实方式。没有发现时明确说明，并交代审查范围及未核实内容。完成条件是审查范围内的适用要求均已核对，每项发现可追溯、每项未核实内容已标出；返回总体工作流第 4 步复核，文档改写另按修改分支执行。
