# PRD 阶段任务流程

## 执行步骤

1. **核对产品证据**
   - 以已有产品说明、客户反馈、访谈、分析数据、设计稿和决策记录为依据，核对是否支撑本次产品问题。
   - 访谈注明出处与日期；数据注明口径、时间范围和来源，未知则标明。个别反馈不代表全体用户，相关性不能作为因果证据。
   - 完成时，关键问题已有来源，缺少的证据已列为待核实。

2. **分析需求**
   - 梳理目标用户、场景、当前做法、问题影响、预期结果、范围、优先级、成功指标、验收、依赖和风险。
   - 用用户可感知的结果描述需求；PRD 可记录已知技术约束，具体实现留到 TDD。
   - 完成时，每项核心需求已有验收条件，或关联到会影响它的未决事项。

3. **处理决策与评审评论**
   - 按入口的提问规则处理影响用户、目标、范围、优先级或验收的选择。
   - 逐条处理评审评论：已确认结论回填需求与决策记录，待用户选择集中列入“待评审决策”，事实或实现核验转为验证/TDD 事项。
   - 完成时，每条评论均有处理结果或未决记录，关联需求状态已同步。

4. **起草或修改**
   - 起草前读取 [内容规范](document.md)，局部修改只读受影响部分。创建或重构文档结构时，再按已选量级读取 [常规模板](template-standard.md) 或 [深入模板](template-detailed.md)；沿用已有结构时无需加载模板。
   - 按规范填写内容。
   - 完成时，核心问题、目标、范围、预期结果和验收条件明确，或已关联未决事项；需求状态与待评审决策、决策记录及验证/TDD 事项一致。目标或范围未定时保持草稿。
   - 返回总体工作流第 4 步复核。
