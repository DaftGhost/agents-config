# Dual Workflow

Dual splits the selected document type's format into two documents. Preserve the type's section order within each document: sections marked *what* go in `what-to-do.md`; sections marked *how* or *how and acceptance* go in `how-to-do.md`.

1. Complete the investigation needed to establish feasibility, then write `what-to-do.md` as Draft. Stop for user confirmation even if both documents were requested. Tell the user that design follows confirmation.
2. After confirmation, change only the status of `what-to-do.md` to Confirmed. Recheck relevant project context if missing or changed, then write `how-to-do.md` as Draft. If a requirement cannot be met or a newly discovered impact changes scope, ask before changing the confirmed requirements.
