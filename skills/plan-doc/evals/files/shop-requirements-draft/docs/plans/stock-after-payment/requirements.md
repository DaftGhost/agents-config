# 库存扣减改为支付成功后：需求

状态：草稿（待用户确认）
档位：双文档（涉及订单、库存、支付回调三个模块，并改变库存变化的时点）

## 概述

当前下单即扣减库存，未支付订单长期占用库存。目标：库存在支付成功后才扣减，未支付订单超过 30 分钟自动关闭。变化影响下单、支付回调、订单取消三处行为，以及依赖订单状态的页面和报表。

## 现状

- 下单时立即扣减库存；订单未支付也一直占用库存，不会自动关闭。
- 取消订单时恢复库存。
- 依赖订单状态的页面和报表只认识现有状态。
- 上线时已存在的未支付订单已按旧规则扣减过库存。
- 约束：
  - 支付网关对同一笔支付最多重试回调 5 次（README）。
  - 业务定时任务最小间隔 5 分钟（README、deploy/crontab）。
  - 退款 API 尚未接入（README）。

## 需求

- 在范围内：下单、支付回调、订单取消、未支付订单超时关闭。
- 不在范围内：价格计算、库存预占、退款流程、前端页面。

| ID | 需求 | 验收标准 |
|----|------|----------|
| R1 | 下单时只校验库存是否充足，不扣减库存。 | 下单后库存数量不变；库存不足时下单被拒绝。 |
| R2 | 支付成功后扣减库存；同一笔支付的重复回调只扣减一次。 | 同一支付连续回调 5 次，库存只减少一次订单数量。 |
| R3 | 支付成功时库存已不足：订单标记为“支付异常”，不扣减库存，并出现在后台支付异常列表中，供运营人工退款。 | 订单状态为“支付异常”；库存不为负数；该订单可在支付异常列表中查到。 |
| R4 | 未支付订单创建 30 分钟后自动关闭，实际关闭时间最多比 30 分钟晚 5 分钟。 | 创建 30 分钟后、35 分钟内订单状态变为已关闭。 |
| R5 | 取消未支付订单不改变库存；取消已支付订单后恢复库存。 | 两种取消后库存数量符合 R5 描述。 |

## 差距

| 需求 | 现状 | 要求 | 约束下如何达成 |
|------|------|------|----------------|
| R1 | 下单即扣减库存 | 下单只校验不扣减 | 无约束冲突 |
| R2 | 支付成功不改变库存 | 支付成功扣减且只扣一次 | 网关最多重试 5 次，因此要求重复回调只扣一次 |
| R3 | 无“支付异常”状态和列表 | 库存不足时标记异常并进入列表 | 退款 API 未接入，因此由运营人工退款 |
| R4 | 未支付订单不会关闭 | 30 分钟后关闭 | 定时任务最小间隔 5 分钟，因此允许最多晚 5 分钟 |
| R5 | 任何取消都恢复库存 | 只有已支付订单取消时恢复 | 无约束冲突 |
