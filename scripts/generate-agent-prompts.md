# 提示词生成向导：功能说明

本文说明 [generate-agent-prompts.sh](generate-agent-prompts.sh) 的完整使用流程、章节合并规则和写入边界。所有运行逻辑集中在这一个 Bash 脚本中。独立的测试用例规格见 [generate-agent-prompts-tests.md](generate-agent-prompts-tests.md)，后续修改功能时，先更新用例，再据此修改实现和编写测试。README 只保留使用入口。

## 1. 用途与运行条件

这个向导（wizard）将仓库的共享指令与可选模块写入一个或多个代理配置文件，或将选定模块合并到已有配置中。它生成文件中的提示词（prompt），不负责确认代理程序是否重新加载了配置。

在仓库根目录运行：

```bash
./scripts/generate-agent-prompts.sh
```

- 运行脚本使用 Bash；使用常见文件工具，包括 `dirname`、`mktemp`、`cat`、`wc`、`tr`、`cp`、`mkdir`、`chmod`、`mv`、`rm`、`cmp`、`head`、`tail`。追加模式还使用 `iconv` 校验 UTF-8，使用 `stat` 读取权限位；支持 GNU 和 BSD 的 `stat` 参数格式。
- 标准输入必须连接交互终端；通过管道传入答案会被拒绝。运行路径依据脚本所在目录确定，不依赖调用时的工作目录。
- 替换模式要求仓库中的 `.agents/AGENTS.md` 存在。
- 两种模式均不需要 Python 或其他脚本解释器。未选择 aside 的追加模式直接退出，不写入文件。
- 追加模式将原文件和 aside 按 UTF-8 解码；无法读取、解码或解析时，报错退出。
- aside 从 `aside/*/*.md` 自动发现，只扫描每个一级子目录下的 Markdown 文件；界面显示相对名称，例如 `tones/warm.md`。添加符合该位置规则的文件后，无须修改脚本即可选用。

## 2. 两种写入模式

一次运行只选择一种模式，应用到本次所有目标。

| 行为 | `1`：替换（默认） | `2`：追加 |
| --- | --- | --- |
| 已有普通文件（regular file） | 确认后替换整个文件 | 确认后合并选定 aside，保留未覆盖内容 |
| 符号链接（symbolic link） | 确认后将链接路径替换为普通文件，原链接指向的文件不变 | 跳过并说明原因，包括失效链接和指向目录的链接 |
| 尚不存在的路径 | 确认后创建文件，必要时创建父目录 | 跳过并说明原因，不创建目标文件 |
| 共享指令 | 始终包含 `.agents/AGENTS.md` | 不添加或刷新共享指令 |
| 未选择 aside | 仍可写入共享指令 | 不写入任何文件 |
| 多目标输出 | 所有确认目标得到相同内容 | 根据各目标原文分别合并，结果可能不同 |
| 写入后的权限位（permission bits） | 设置为 `0644` | 保留原文件的权限位 |

替换模式按以下顺序拼接：共享指令、所选 aside。每个 aside 前插入两个换行字符 `\n\n`，各来源文件本身的内容不变。替换模式不检查 aside 是否符合追加模式的章节结构。

## 3. 交互流程与目标选择

```mermaid
flowchart LR
    mode[选择写入模式] --> targets[选择目标路径]
    targets --> asides[选择 aside]
    asides --> preview[生成每个适用目标的完整预览]
    preview --> confirm[逐个确认是否写入]
    confirm --> write[复查目标并写入]
    write --> verify[比对内容并报告结果]
```

### 第一步：选择写入模式

输入 `1` 或直接按 Enter，使用替换模式；输入 `2`，使用追加模式。其他输入会提示重新选择。

### 第二步：选择目标代理与路径

| 选项 | 名称 | 目标路径 |
| --- | --- | --- |
| `1` | Claude | `~/.claude/CLAUDE.md` |
| `2` | Codex | `~/.codex/AGENTS.md` |
| `3` | Shared agents | `~/.agents/AGENTS.md` |
| `4` | DSH | `~/.dsh/AGENTS.md` |
| `5` | 自定义 | 输入一个或多个文件路径 |

输入逗号分隔的编号，例如 `1,2,5`。`all` 只选择预设选项 `1`～`4`，不进入自定义输入。预设按输入顺序加入，使用 `all` 时按显示顺序加入；自定义路径随后加入。重复编号不会重复加入，目标选择不能为空。

选择 `5` 后，每行输入一个路径。至少输入一个有效路径后，空行结束自定义输入；尚未输入有效路径时，空行会提示继续输入或按 Ctrl-C 取消。

自定义路径规则：

- 接受绝对路径及以 `~/` 开头的路径；`~` 会展开为用户主目录，再按文件路径规则验证。
- 拒绝以 `/` 结尾的目录路径、已有且不是符号链接的目录、已有且不是普通文件的其他路径，以及父路径已存在但不是目录的路径。
- 接受符号链接和不存在的路径，再按所选模式决定替换、创建或跳过。
- 输入路径与共享指令文件或已发现 aside 的源路径完全一致时，拒绝作为输出目标。
- 展开 `~` 后，与已选目标路径字符串完全一致的输入不会重复加入。该检查不解析路径别名，不保证不同写法指向不同文件。

### 第三步：选择 aside

输入逗号分隔的编号，例如 `2,1`；按输入顺序处理，重复编号只保留首次选择。输入 `all` 按显示顺序选择全部文件；空行表示不选择 aside。非法编号会要求重新输入。

### 第四步：预览、确认与写入

使用 `stage` 展示四个阶段的进度，每次切换阶段清屏。输入使用 `ask`，不保存本次选择。终端支持 `tput` 时使用其颜色和清屏能力；缺少可用清屏能力的终端使用 ANSI 能力。成功写入后使用 `finish`，并汇总已写入和保持不变的目标。

先列出模式和输入文件，再展示每个适用目标的完整输出与字节数。追加模式的符号链接、不存在的路径直接列为跳过目标，不要求写入确认。

所有预览完成后，逐个询问是否写入。只有单个 `y` 或 `Y` 表示同意；空行及其他回答都表示跳过。拒绝一个目标不影响其他目标的确认。没有确认目标时，报告未写入并正常退出。

## 4. 追加模式的章节合并规则

### 支持的输入结构

每个 aside 的首个非空内容必须是井号标题（ATX heading），正文可以包含层级更深的子标题。主标题之前可以有空白，但不能有正文；主标题之后不能再出现同级或更高级标题。当前仓库的 aside 均采用一个二级主标题及其子章节。

标题规则如下：

- 使用 `#`～`######`，行首允许最多三个空格；非空标题的井号后需要空格或制表符。
- 比较时采用井号数量和标题文字，文字区分大小写；忽略文字两端空格、制表符以及合法的末尾关闭井号。
- 末尾关闭井号前需要空白。例如 `## Rule ###` 匹配 `## Rule`；`## Rule#` 的标题是 `Rule#`，不匹配 `Rule`。
- 不比较父标题，因此不同父章节内的同名、同层级标题也可以匹配。
- 忽略围栏代码块（fenced code block）内部的标题。支持至少三个连续反引号或波浪线；关闭围栏必须使用同一种字符，长度至少等于开启围栏，后面只能有空白。
- 不将四个空格缩进的标题行视为标题，也不解析下划线标题（Setext heading）、列表或引用块中的嵌套标题。该工具不实现完整 Markdown 解析。
- 原文件或 aside 含有未关闭围栏时，拒绝合并，避免将追加内容写进代码示例。

### 覆盖与追加

按选择顺序处理每个 aside：

1. 找到目标文件中第一个同名、同层级标题。
2. 匹配时，从该标题开始，替换到下一个同级或更高级标题之前；原章节正文和所有子章节一并替换。
3. 后面其他同名、同层级章节保留原文。不同层级或大小写不同的标题也保留。
4. 没有匹配时，将整个 aside 章节追加到文件末尾，必要时补上换行和分隔空行。
5. 后选择的同名、同层级模块覆盖先前合并结果中的首次匹配章节。

新章节末尾缺少换行时补上 `\n`。替换时，aside 自带的末尾空行优先；aside 没有末尾空行时，保留旧章节的末尾分隔空行。未覆盖区域保留原始字节，包括已有的 `\r\n`。对相同结果重复应用同一组 aside，输出保持不变。

包含两段同名 `## Rule` 的完整示例见 [TC-001](generate-agent-prompts-tests.md)。

## 5. 写入保护、失败处理与边界

追加模式在生成预览前复制目标，形成保留权限的原文快照（snapshot），并在独立临时文件中生成合并结果。所有目标的预览生成完成后才进入确认阶段，因此读取、解码或解析失败时，不会先写入其他目标。

写入阶段的行为：

- 目标逐个写入，不构成多个文件间的整体事务；某次写入失败会停止后续写入，已经完成的目标保持已写入状态。
- 写入前复查目标类型。审核过的符号链接已不再是链接、其他目标变成符号链接或非普通文件、待创建路径已经出现时，拒绝写入。
- 追加目标在替换前还会与原文快照比对；内容变化、文件消失或类型变化时，停止并报告目标路径。
- 在目标同一目录创建临时输出，再替换目标；写入后用 `cmp` 与预览内容比对，确认实际文件内容一致。
- 替换符号链接时，先将原链接移到临时位置；写入失败则尝试恢复链接。恢复也失败时，报告原链接保留的位置，供人工处理。
- 正常退出、错误退出及捕获到 `SIGINT`、`SIGTERM` 时清理预览、快照和准备中的临时输出。链接恢复失败时留下的原链接不作为普通临时文件删除。
- 成功写入后报告 `Wrote <路径>`，正常完成报告 `Prompt generation complete.`。追加模式未选择 aside 或没有确认目标也正常退出；被脚本明确拒绝的错误返回非零状态。捕获到 `SIGINT`、`SIGTERM` 时分别以 `130`、`143` 退出。

这些检查不锁定文件；检查和替换之间仍可能有并发修改。保留的属性是权限位，不承诺保留文件所有者、扩展属性或其他元数据。原文快照只用于本次运行的检查，退出后删除，不是长期备份。发生部分写入后，可以根据已报告的路径重新运行；追加模式的重复合并不会重复添加相同章节。

## 6. 单文件结构与内部接口

唯一运行入口是 `generate-agent-prompts.sh`。共享指令和 aside 是输入数据，章节合并无需另一个脚本。直接执行时启动四阶段交互向导；用 Bash `source` 加载时只定义函数，不启动交互或创建临时文件。

向导内部调用同一文件中的 Bash 函数：

```bash
merge_sections ORIGINAL OUTPUT [ASIDE ...]
```

| 参数 | 含义 |
| --- | --- |
| `ORIGINAL` | 读取的原文件 |
| `OUTPUT` | 输出合并结果的文件，已有文件会被覆盖 |
| `ASIDE` | 按参数顺序处理的 aside 文件；没有参数时复制原文 |

函数校验 UTF-8，使用 Bash 识别标题，并通过文件工具保留未覆盖区域的原始字节；字符编码或章节结构错误输出 `Cannot merge aside sections: ...` 并返回 `1`，文件工具错误返回非零状态，成功返回 `0`。函数在子进程中处理临时文件并清理，不改变调用者的 Shell 选项或退出处理。预览确认、目标筛选、写前变化检查、权限保留及同目录临时替换由向导流程完成。
